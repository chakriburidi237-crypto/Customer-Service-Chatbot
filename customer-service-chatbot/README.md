# Customer Service AI Chatbot

An NLP-based intent-classification chatbot — not a rule-based one — that understands customer messages, classifies intent, extracts entities (order numbers, dates), and routes low-confidence input to a graceful fallback instead of guessing. Built as one of two required projects for the Codec Technologies 1-Month AI Internship.

## Overview

- **Model**: TF-IDF (unigrams + bigrams) + Logistic Regression
- **Performance**: **82.1% intent classification accuracy**, 0.81 macro F1 across 10 intents, tested on 278 labeled training phrases
- **Confidence-based fallback**: predictions below a 0.35 probability threshold are routed to a fallback intent instead of a wrong guess
- **Entity extraction**: regex-based extraction of order numbers (`#12345`, `ORD-9821`) and dates from raw messages
- **Multi-turn context**: session-based memory — if you mention an order number once, the bot remembers it for follow-up messages in the same conversation
- **Backend**: FastAPI (`/chat`, `/intents`, `/health`, session reset) with bounded request validation and processing-time telemetry
- **Quality**: Automated regression tests cover intent routing, entity carry-over, safe fallback, and session reset
- **Frontend**: Responsive AI operations workspace with quick actions, live confidence meter, extracted entities, ranked alternatives, and explainable session reset

## Setup

```bash
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Train the model

```bash
python train.py
```

Trains on `data/intents.json`, prints a classification report, and saves the pipeline + response templates to `models/`.

Run training after installing the pinned dependencies so the serialized scikit-learn model matches the runtime environment. This avoids compatibility warnings when loading the `.joblib` artifact.

## Evaluate

```bash
python evaluate.py
```

Prints accuracy, macro F1, and a per-class report, and saves a confusion matrix heatmap to `models/confusion_matrix.png`.

## Run the app

```bash
uvicorn app:app --reload
```

Open **http://127.0.0.1:8000** and chat. Use the quick actions for a fast demo, or ask a question with an order number and watch the decision trace update with the detected intent, confidence score, ranked alternatives, and extracted entities.

## API

**POST** `/chat`

```json
{ "message": "where is my order #45210", "session_id": "abc123" }
```

Response:

```json
{
  "reply": "Let me check that for you. Could you share your order number if you haven't already? (Order reference: #45210)",
  "intent": "order_status",
  "confidence": 0.88,
  "entities": { "order_number": "#45210" },
  "alternatives": [
    { "intent": "order_status", "confidence": 0.88 },
    { "intent": "cancel_order", "confidence": 0.03 },
    { "intent": "complaint", "confidence": 0.02 }
  ]
}
```

**GET** `/intents` — lists all supported intents.

**GET** `/health` — returns service status, model name, intent count, and the confidence threshold.

**DELETE** `/sessions/{session_id}` — clears the conversation context for a session.

The `/chat` response also includes `needs_clarification` when the confidence guard routes a message to fallback, plus `processing_ms` for lightweight inference observability. Requests are limited to 500 characters and session IDs to 100 characters.

## How confidence-based fallback works

Every prediction returns a probability distribution over all intents (via `predict_proba`). If the top probability is below `CONFIDENCE_THRESHOLD = 0.35` (set in `app.py`), the bot routes to `fallback` and asks the user to rephrase rather than confidently returning a wrong intent. This is the difference between a chatbot that "sounds smart" and one that quietly gives wrong answers.

## Notes / next steps

- `complaint` has the lowest per-class F1 (0.40) since it shares vocabulary with `refund_request`, `order_status`, and `product_info` (e.g. "broken", "wrong item") — a realistic limitation to mention in interviews, and a good motivator for why a larger dataset or a transformer-based model (e.g. fine-tuned `distilbert-base-uncased`) would help most.
- The classifier is structured as a scikit-learn `Pipeline`, so swapping in a transformer-based intent classifier later is a drop-in replacement — no changes needed to `app.py`'s calling code beyond loading a different model object.
- To extend: add real conversation logs (with PII scrubbed) to `data/intents.json` for further fine-tuning, or connect entity extraction to a real order-lookup database instead of just echoing the number back.
